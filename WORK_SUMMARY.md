## 🚀 How to Implement (Next Steps)

### Quick Start (45 minutes)

#### 1. Generate BETTER_AUTH_SECRET
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# Copy the output (32-char hex string)
```

#### 2. Create .env.local
```bash
cp .env.example .env.local

# Edit .env.local and add:
BETTER_AUTH_SECRET=<your-32-char-hex>
BETTER_AUTH_URL=http://localhost:3000
DATABASE_URL=<your-neon-string>
DATABASE_URL_UNPOOLED=<your-neon-unpooled>
RESEND_API_KEY=<your-resend-key>
EMAIL_FROM=LearnDE <noreply@learnde.dev>
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

#### 3. Migrate Database
```bash
npm install
npm run db:push  # Creates all tables in Neon
```

#### 4. Start Development
```bash
npm run dev
# Visit http://localhost:3000/auth/register
# Test sign-up → role selection → dashboard
```

#### 5. Test Flows
- Sign-up: Create account → Choose role → See dashboard
- Sign-in: Enter credentials → See dashboard
- Protected routes: Try /dashboard when logged out → Redirected to login
- Role-based: Student can't access /staff, etc.

#### 6. Deploy to Vercel (Optional)
```bash
git push origin main
# Vercel auto-deploys
# Add env vars in Vercel dashboard
# Test on production
```

## 🚨 Common Issues & Solutions

| Issue | Solution |
|-------|----------|
| "BETTER_AUTH_SECRET is required" | Add 32-char hex string to .env.local |
| Database connection error | Verify DATABASE_URL is correct |
| Sign-up stuck on role selection | Check /api/auth/set-role endpoint |
| Middleware blocking all routes | Restart dev server, clear .next folder |
| Session not persisting | Verify BETTER_AUTH_SECRET (min 32 chars) |
| Can't access protected routes | Check middleware.ts matcher config |
